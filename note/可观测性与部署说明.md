
## 1. 观测入口

应用默认提供：

- `GET /actuator/health`：存活和就绪检查
- `GET /actuator/info`：应用信息
- `GET /actuator/prometheus`：Prometheus 指标

Actuator 只暴露 `health`、`info` 和 `prometheus`，生产环境应限制 Actuator 的访问来源。

## 2. 请求关联 ID

每个 HTTP 请求都会生成或透传 `X-Request-Id`。未携带时服务生成 UUID，响应返回同名请求头，日志 MDC 字段为 `requestId`。Webhook 返回 `202` 后，后台异步审查会继续使用接收请求的关联 ID，可以用它搜索整条处理链路。

## 3. 关键指标

| 指标 | 标签 | 含义 |
| :--- | :--- | :--- |
| `jayagent_webhook_received_total` | `platform` | Webhook 接收次数 |
| `jayagent_webhook_rejected_total` | `platform`, `reason` | 认证或请求校验拒绝次数 |
| `jayagent_webhook_duplicate_total` | `platform` | 重复事件次数 |
| `jayagent_review_total` | `source`, `result` | 审查成功/失败次数 |
| `jayagent_llm_call_duration_seconds` | `result` | LLM 调用耗时 |
| `jayagent_rag_search_duration_seconds` | `result` | RAG 检索耗时 |
| `jayagent_external_api_total` | `system`, `operation`, `result` | GitHub/GitLab/企业微信调用结果 |
| `jayagent_external_api_duration_seconds` | `system`, `operation` | 外部 API 调用耗时 |
| `jayagent_wechat_notification_total` | `result` | 企业微信告警成功/失败次数 |

## 4. 排障路径

使用响应中的 `X-Request-Id` 搜索日志，先区分 Webhook 接收、拒绝、重复事件，再区分 `external_api_failure`、`review_failed` 和 `wechat_alert_failed`。通过审查计数、LLM Timer 和 RAG Timer 判断失败率与耗时。生产日志输出为 JSON，包含时间、应用名、级别、logger、线程、message、MDC 和异常堆栈字段。

## 5. Webhook 完成链路

当前 Webhook 任务先写入 SQLite 任务表，再由 `WebhookReviewTaskDispatcher` 轮询并执行。日志使用以下字段串联一次处理：

| 字段 | 来源 | 用途 |
| :--- | :--- | :--- |
| `requestId` | `X-Request-Id` 或服务生成 | 串联 HTTP 接收和后台执行日志 |
| `taskId` | `webhook_review_task.id` | 定位持久化任务、重试和最终状态 |
| `platform` | `github` / `gitlab` | 区分平台链路 |
| `attempt` | 任务执行次数 | 判断是否发生重试 |

典型日志顺序为：`webhook_task_enqueued` -> `webhook_task_dispatching` -> `webhook_task_started` -> `review_completed` -> `webhook_task_completed`。失败时会出现 `webhook_task_retry_scheduled` 或 `webhook_task_failed`。任务状态包括 `PENDING`、`RUNNING`、`SUCCEEDED` 和 `FAILED`。

## 6. 生产告警规则

以下规则是建议的起步边界，窗口和阈值应按实际流量校准：

```yaml
groups:
  - name: jayagent-review
    rules:
      - alert: JayAgentWebhookRejectRateHigh
        expr: sum(rate(jayagent_webhook_rejected_total[5m])) / clamp_min(sum(rate(jayagent_webhook_received_total[5m])), 1) > 0.2
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: Webhook rejection rate is high

      - alert: JayAgentReviewFailureRateHigh
        expr: sum(rate(jayagent_review_total{result="failure"}[10m])) / clamp_min(sum(rate(jayagent_review_total[10m])), 1) > 0.1
        for: 10m
        labels:
          severity: critical
        annotations:
          summary: Review failure rate is high

      - alert: JayAgentExternalApiFailure
        expr: sum(rate(jayagent_external_api_total{result="failure"}[5m])) > 0
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: External platform API failures detected

      - alert: JayAgentWebhookTaskBacklog
        expr: increase(jayagent_webhook_task_failed_total[15m]) > 0
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: Webhook review tasks are failing
```

说明：当前任务状态和失败次数主要通过结构化日志追踪；若需要直接按任务状态告警，应继续增加任务队列 Micrometer 计数器，例如 pending、running、retry 和 failed gauge/counter。

## 7. JAR、Docker 与多实例

JAR 运行需要 API Key、DeepSeek Key、可访问的 Elasticsearch 和可写的 `data/` 目录。历史数据库、Webhook 去重文件和知识库状态文件都属于外部状态，升级时应保留。

Docker 应挂载 `data/` 持久化目录，应用容器使用 `http://elasticsearch:9200`，Prometheus 从 `8080/actuator/prometheus` 抓取指标。Compose 同时为 Elasticsearch 和 JayAgent-review 配置健康检查，并要求应用在 Elasticsearch 健康后再启动。

文件型去重只适合单实例。多实例必须共享同一个 SQLite 文件和持久化卷；跨主机生产部署建议将去重迁移到 Redis 或集中式数据库。当前异步任务已经通过任务表承接，但执行仍依赖进程内调度，实例重启后未完成任务可重新捞取，稳定性优于纯内存线程池，但还可以继续演进到外部队列。

### 7.1 数据备份边界

宿主机 `data/` 是应用的持久化边界，建议停止 `jayagent-review` 后备份以下文件：

| 文件 | 数据类型 | 恢复价值 |
| :--- | :--- | :--- |
| `review-history.db` | 审查历史、筛选和统计 | 必须备份 |
| `webhook-review-task.db` | Webhook 任务、重试次数和失败状态 | 必须备份 |
| `webhook-events.log` | 文件型去重事件 | 建议备份 |
| `knowledge-base-state.txt` | 规则源文件哈希状态 | 可重建，建议保留 |

恢复时先停止应用，复制当前 `data/` 作为回滚副本，再替换目标文件并启动应用。启动后检查容器健康状态、Actuator 健康接口、历史查询和任务状态。不要把 `.env`、真实密钥或整个 Docker 镜像层作为数据备份。
