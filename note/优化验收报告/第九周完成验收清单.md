# 第九周完成验收清单

> 第九周围绕 P2 可维护性展开，目标是降低核心类的职责密度，统一接口错误响应，并补齐 API 文档。重点不是改变业务行为，而是让后续开发、测试和排障更容易进行。

> 后续状态：第九周核心重构已完成。Webhook 安全、解析、Diff 组装和异步编排已经分别落到 `WebhookSecurityService`、平台 Parser、`DiffAssembler` 和 `WebhookReviewOrchestrator`；第四阶段又补充了请求关联 ID、JSON 日志和 Prometheus 指标。

## 一、本周优化目标

本周主要解决五类问题：

1. `WebhookController` 业务、解析、鉴权和异步调度职责过多。
2. `JayAgentScanner` 同时负责检索、Prompt 构建、模型调用和结果解析。
3. `ReviewHistoryService` 同时承担持久化、查询、统计、迁移和数据模型职责。
4. 多个接口直接返回 `Map<String, Object>`，响应契约不够明确。
5. 异常处理没有统一入口，API 文档也不完整。

---

## 二、优化前存在的问题

### 2.1 `WebhookController` 过重

原控制器同时负责：

- 请求体大小和 Content-Type 校验
- GitHub / GitLab 鉴权
- JSON 解析
- Webhook 去重
- 平台 payload 字段提取
- diff 拼接
- 异步任务提交
- 调用外部 API
- 触发审查和评论

这导致一个类同时承载入口安全、数据解析、业务编排和异步执行，修改任意一块都可能影响其他行为。

### 2.2 `JayAgentScanner` 过重

原扫描器同时负责：

- 构造知识库检索语句
- 组装 Prompt
- 调用向量库
- 调用 LLM
- 解析 `SUMMARY|` 和 `RISK|`
- 生成默认摘要

扫描器的主流程不够突出，解析规则也不容易独立测试。

### 2.3 `ReviewHistoryService` 职责偏重

历史服务同时承担：

- SQLite 连接和建表
- JSONL 迁移
- 审查记录转换
- 保存
- 分页查询
- 条件筛选
- 统计
- 趋势
- 详情读取

本周先保留其对外行为不变，明确其职责边界，为后续继续拆分 Repository、Mapper 和统计查询组件留出空间。

### 2.4 API 响应结构不统一

部分接口直接返回 `Map<String, Object>` 或 `List<Map<String, Object>>`，调用方需要依赖字符串 key 猜测字段。

这种方式的问题是：

- 字段拼写错误只能运行时发现
- API 契约不集中
- 前端和测试难以复用响应模型

### 2.5 异常处理和 API 文档不足

不同入口的异常可能由 Spring 默认处理，也可能直接抛出 `ResponseStatusException`，调用方得到的错误结构不统一。

同时，接口缺少集中说明，学习者需要从多个 Controller 反向推断请求参数、状态码和响应字段。

## 三、本周实施的优化

### 3.1 拆分扫描 Prompt 构建职责

新增 `ReviewPromptBuilder`，负责：

- 构造知识库检索语句
- 过滤最低相似度
- 格式化知识库上下文
- 构造系统 Prompt

`JayAgentScanner` 保留主流程：

1. 规范化输入
2. 调用 Prompt 构建器生成检索条件
3. 查询知识库
4. 调用模型
5. 交给结果解析器
6. 记录耗时并返回报告

作用是让扫描器更接近“流程编排器”，而不是规则和字符串处理的集合。

代码落点：

- [`JayAgentScanner.java`](/F:/JayAgent/JayAgent-review/src/main/java/com/jayagent/jayagent_review/agent/JayAgentScanner.java)
- [`ReviewPromptBuilder.java`](/F:/JayAgent/JayAgent-review/src/main/java/com/jayagent/jayagent_review/agent/ReviewPromptBuilder.java)

### 3.2 拆分模型结果解析职责

新增 `ReviewReportParser`，集中处理：

- `SUMMARY|` 摘要行
- `RISK|` 风险行
- 新旧两种风险字段格式
- 风险等级图标
- 置信度范围归一化
- 默认摘要

这样模型输出格式变化时，主要修改解析器，不需要改动扫描主流程。

代码落点：

- [`ReviewReportParser.java`](/F:/JayAgent/JayAgent-review/src/main/java/com/jayagent/jayagent_review/agent/ReviewReportParser.java)
- [`JayAgentScanner.java`](/F:/JayAgent/JayAgent-review/src/main/java/com/jayagent/jayagent_review/agent/JayAgentScanner.java)

### 3.3 增加统一异常响应入口

新增 `ApiExceptionHandler`，统一处理：

- `ResponseStatusException`
- 参数校验异常
- 未预期异常

统一错误响应至少包含：

- `success`
- `status`
- `message`
- `timestamp`

作用是让前端和调用方不需要针对不同 Controller 编写多套错误解析逻辑。

代码落点：

- [`ApiExceptionHandler.java`](/F:/JayAgent/JayAgent-review/src/main/java/com/jayagent/jayagent_review/controller/ApiExceptionHandler.java)

### 3.4 保持已有 API 行为兼容

本次重构没有改变既有业务字段和主要状态码：

- Webhook 仍然返回 `202`
- 手动扫描仍返回 `success`、`reviewScope`、`score`、`risks`、`summary`
- 历史接口仍返回分页、统计和趋势字段
- 默认不暴露 `rawAnalysis`

这样可以降低前端和已有测试的迁移成本。

## 四、接口说明

主要 API：

| 方法 | 路径 | 用途 | 成功状态 |
|---|---|---|---|
| `POST` | `/api/jayagent/scan` | 手动代码审查 | `200` |
| `GET` | `/api/jayagent/history` | 历史分页查询 | `200` |
| `GET` | `/api/jayagent/history/{id}` | 历史详情 | `200` |
| `GET` | `/api/jayagent/stats` | 历史统计 | `200` |
| `POST` | `/api/webhook/github` | GitHub Webhook | `202` |
| `POST` | `/api/webhook/gitlab` | GitLab Webhook | `202` |
| `GET` | `/api/search/test` | 知识库检索测试 | `200` |
| `GET` | `/api/chat/test` | 模型连通性测试 | `200` |
| `POST` | `/api/rules/refresh` | 规则刷新入口 | `200` |

通用错误状态：

- `400`：请求参数或 JSON 不合法
- `401`：鉴权失败
- `403`：请求被拒绝
- `413`：Webhook 请求体过大
- `415`：Content-Type 不支持
- `503`：服务依赖或鉴权配置不可用
- `500`：未预期服务端异常
